---
title: "哪些操作会消耗 token"
description: "了解 OpenWork 的模型用量从什么时候开始产生，以及如何管控它。"
---

OpenWork 只有在成员真正跑任务时才消耗模型 token。光是配置动作本身不会消耗 token。

## 搞清楚用量从什么时候开始

1. 发送一条提示词就会运行所选模型并消耗 token。运行一个技能也一样，因为技能会被加载进任务，模型要照着它的说明执行。
2. 目前没有结果缓存：重跑同一个任务会发出一次新的模型请求。
3. 用量随智能体不得不读取的上下文规模增长，包括很长的对话记录、粘贴进来的文本、文件附件和工具结果。
4. 工具调用越多的任务通常越贵，因为智能体要读取结果并决定下一步。
5. 提示词卡片放在策略里时不产生任何费用，管理员配多少张都不影响。安装技能，或通过 Collection 发布插件，同样在成员跑出一个用到它们的任务之前不产生费用。
6. 一个好技能能降低成本，因为它把重复工作做得更短、更确定，试探性的工具调用也更少。

## 现在可以怎么管控开销

1. 让提示词卡片保持简短、具体。
2. 重复性的工作流，优先用职责单一的技能。
3. 只附上这个任务真正需要的文件和对话上下文。
4. 先要窄范围的输出，再做大范围分析。
5. 留意那些在很多工具之间反复循环的任务，然后把跑通的那条路径做成一个技能。
