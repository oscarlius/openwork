---
title: "控制浏览器"
description: "如何用 OpenWork 自动化内置浏览器"
---

访问网站时，请使用 OpenWork 内置的 Browser。

OpenWork 可以在这个浏览器里打开页面、点击、填表单、读取页面内容并截图。浏览器运行在 OpenWork 桌面应用内；云端工作进程和 OpenWork Web 没有浏览器。

目前受支持的路径是官方自带的 `OpenWork Browser` 扩展。

## 前置条件

- 使用 OpenWork 桌面应用。
- 在 `Settings > Library` 里保持 `OpenWork Browser` 处于启用状态。

之后回到会话视图，让 OpenWork 打开一个网站即可。

## 为某个会话放开控制权

浏览器面板会问你 **Allow browser control for this thread?**。选一次 **Allow for this thread**，这段对话就可以在你允许的站点之间导航、读取页面，并在它自己打开的标签页里滚动。你不需要对每个页面、每次滚动都单独批准。组织的限制依然生效。

点击、输入和键盘操作在执行前仍然会问 **Allow browser action?**，因为它们会用你已登录的账户提交信息或改动站点数据。请先确认目标和文本，再选择 **Allow once** 或 **Deny**。核对花费的时间不会消耗那个很短的页面观察窗口，但页面或目标一旦变化，就需要重新观察一次。浏览器操作始终受时间上限约束。键盘自动化要求有一个真正获得焦点的原生输入框、按钮或链接；无法确认焦点的内嵌编辑器和自定义编辑器需要你手动接管。

任何时候都可以选择 **Take over** 来暂停浏览器操作并收回授权。你可以直接在页面里登录，然后选择 **Resume browser**；下一次浏览器操作会重新申请授权。关闭浏览器控制、取消一个正在进行的浏览器操作、关掉该会话的最后一个浏览器标签页，或者重启桌面应用，同样会清除这次授权。授权永远不会转移到另一个会话。

网站工具（WebMCP）仍然需要单独批准才能运行，而且它们的结果在你选择 **Share result** 之前一直是本地的。浏览器控制权不会把访问范围扩展到日常使用的 Chrome 配置文件，也不会扩展到其他会话的标签页。

为浏览器工作而打开或恢复的标签页会一直处于受保护状态，直到 `browser.release_tab` 声明所有运行中和排队中的工作都已完成。Release 不会挂起或作废当前的目标，也不存在自动回收。后续工作请用 `browser.restore_tab`，它会校验会话归属，并返回一个可供使用的、全新的受保护句柄。

## 键盘快捷键

在桌面应用里，当内置浏览器页面、它的地址栏或它的浏览器控件获得焦点时，下列快捷键生效：

| 操作 | macOS | Windows / Linux |
| --- | --- | --- |
| 关闭当前获得焦点的浏览器标签页，OpenWork 保持打开 | `Cmd+W` | `Ctrl+W` |
| 重新打开该会话最近关闭的那个浏览器标签页 | `Cmd+T` | `Ctrl+T` |

原生应用菜单里的 **Close** 命令，也会在关闭窗口前先关闭当前获得焦点的浏览器标签页。

重新打开会依据一份只保存在内存里的 URL 加载一个全新页面，而不是一份已保存的页面快照。它不会恢复表单填写内容、滚动位置或页面历史；已关闭标签页的 URL 也无法在应用重启后保留。

关掉最后一个浏览器标签页后，请立刻按重新打开的快捷键。在这之前点击别处、按 `Tab` 或切换会话，都会清除那个即时的浏览器上下文。当聊天输入框处于焦点时，`Cmd+T` / `Ctrl+T` 仍然是切换会话，而不是重新打开浏览器标签页。
