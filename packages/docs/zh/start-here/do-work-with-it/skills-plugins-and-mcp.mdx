---
title: "连接器、技能与插件"
description: "用连接器接进系统，用承载技能的插件让这套系统真正可用"
---

OpenWork 给智能体的是一小组构件。连接器负责触达系统；技能是那本操作手册；插件是打包好的组合；Library 则是你查看自己手上有什么的地方。

## 选对使用单位

| 名称 | 含义 | 什么时候用它 |
| --- | --- | --- |
| 连接器（Connector） | 你的组织独立添加的一个 MCP 服务，没有把它包装成插件。 | 你连接一次之后，智能体就需要在那个系统里做事。 |
| 连接（Connection） | 你自己对某个连接器的已登录实例，每个用户一个。 | 你登录进去，让智能体在那个系统里以你的身份行动。 |
| 技能（Skill） | 写下来的说明，任务匹配时智能体才会加载。 | 某一种可重复的工作方式需要一本操作手册。 |
| 插件（Plugin） | 一个打包组合——技能、MCP 服务器和其他组件被打包成一个整体分发。 | 几个相关的部分应当一起交付。 |
| 资源库（Library） | 桌面应用和 Cloud 控制台里，列出了你有权使用的全部生效元素。 | 你想看看或管管自己已经拥有什么。 |

MCP 是许多连接器底下的开放标准，而 [OpenWork MCP 网关](/cloud/run-in-the-cloud/cloud-mcp)是让这一切抵达你智能体的通道——但日常使用中，你完全可以用连接器、技能、插件和资源库这套概念来思考。

## 先把系统接通

应用本身请交给连接器。在桌面应用里，从 **Settings › Library** 起步，按 **Connectors** 筛选；一步步的点击流程见[连接你的服务](/zh/start-here/connect-your-stack/connect-services)。

你的智能体能用的一切，都列在 `Settings` > `Library` 的 `Available apps` 和 `Your apps` 下。要用 `Add Custom App` 接入我们还没列出的东西。

## 连接器太薄时补上技能

连接器可能已经接到了你的工单系统，但用起来依然别扭：一次事故可能需要精确的字段，改优先级可能需要一个安全的顺序，或者某一种工单操作表现很差。

把这些系统规则写成技能：

- 提报一次事故时该填哪些字段；
- 更新客户备注时怎么不丢掉上下文；
- 如何绕开一个不稳定的工单操作。

这类技能描述的是系统本身，而不是某个人的风格，所以每一个使用这套系统的人都需要它们。

## 把系统技能打包成一个插件

说到底，一切都是插件。当你请 OpenWork 创建一个技能时，OpenWork 会创建一个只含这一个技能的小插件，所以“到底选技能还是选插件”并不是大多数人需要做的一次决策。

真正有用的插件场景，是一个很薄的连接器配上多条系统技能。如果六条工单技能刚好让一套系统可用，就把它们打包成一个插件——工单这一个单元——然后共享这一个东西。分发方式见[发布与复制技能](/zh/start-here/do-work-with-it/publish-and-copy-a-skill)。

## 个人技能请单独放

系统交给连接器。让一套系统可用的那些技能，用插件打包起来。个人或特定工作流的技能可以继续保持独立，除非某个团队应当一次性收到它们。
