---

费用是根据记录每个请求时公开列出的模型价格得出的近似值。它们是用量的指示，不是有保证的账单，也不是提供商实际收费的精确记录。

## 从 token 到单个请求的费用

模型提供商会用该请求的 token 消耗来响应，包括消耗的**输入 token** 和生成的**输出 token**。对于流式响应，这份用量信息可能在流的接近末尾处才到达。

Gateway 用这些已上报的计数，为发给提供商的每个请求或提示计算费用：

1. 确定这个请求用到的上游提供商和模型。
2. 读取响应中上报的输入和输出 token 消耗。
3. 套用记录该请求时可获得的定价目录中，该模型的输入与输出单价。
4. 把算出的费用与该请求一起存储。

对于没有缓存、也没有其他单独计价 token 类别的基础请求：

```text
Estimated request cost in USD =
  (input tokens × input price per million tokens
   + output tokens × output price per million tokens) / 1,000,000
```

在已上报用量和可获得定价支持的范围内，Gateway 还会考虑缓存输入、缓存写入、单独上报的推理 token，以及按上下文长度划分的价格档。它会按提供商的响应格式处理各类 token，避免同一批 token 被计两次。

有些提供商会直接返回费用。存在可用的提供商上报费用时，Gateway 记录那个数值，而不再按目录估算。

## 从请求费用到图表合计

Gateway 把各个请求记录的费用相加，得到图中的合计。所选日期范围、筛选条件和分组方式决定哪些请求参与计算。请求会被归到它开始时所在的 UTC 日历日。

桌面应用中的一条消息或一个任务可能触发多个模型请求，比如连续的工具调用步骤或重试。每个费用已知的请求都各自计入合计。

存储金额的精度高于图表中显示的两层小数。Gateway 先把存储的金额求和，再对显示总额做四舍五入，因此把逐个四舍五入后的金额相加可能得到略微不同的结果。一笔极小的已知费用，四舍五入后可能显示为 **$0.00**。

目录中的模型价格发生变化时，已存储的估算不会重算。团队分组跟随当前的团队成员关系，所以属于多个团队的人对每个团队都有贡献。分组和 token 统计的细节见[用量统计](/zh/ai-gateway/counting-usage)。

## 费用不可用时

如果提供商没有上报必需的输入和输出用量，或者 Gateway 找不到该提供商和模型的可用定价，请求就可能没有费用估算。错误、取消、中断和被拒绝的请求同样会让用量不可用。这些情形见[无法计量的项目](/zh/ai-gateway/counting-usage)。

费用图只包含已知费用。缺失的估算会被排除，而不是当作免费；没有任何可用费用数据的模型不会出现在费用视图中。即使缺少 token 总数，提供商上报的费用仍可能可用。

如果请求在失败或被取消之前，已有足够用量可以算出费用，那笔已知费用仍然会计入合计。

## 准确性与局限

我们无法保证费用估算的准确性，也无法保证定价信息的完整性、准确性或新鲜度。在比较活动量和理解用量趋势时，请把这些数字当作**仅为指示**。

- 公开目录价格可能已过时，也可能没有覆盖每一条提供商专属的计费规则或额外收费。
- 估算不反映你可能拥有的合同价、协商折扣、抵扣额度或其他计费约定。
- 提供商用量缺失或不完整时，图表可能只体现出已被计费的那部分活动。
- 即便是提供商上报的费用，经过账务调整后也可能与最终发票不同。

请以你自己提供商的账单记录和发票为准来确定实际费用。
