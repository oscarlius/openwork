AI Gateway 的用量图展示的是经由你所在组织的 Gateway 提供商发出的请求所上报的用量。OpenWork Models 单独跟踪，不计入这张图。

## token 如何统计

Gateway 从提供商的响应中读取 token 用量，包括流式响应里的用量事件。它记录提供商给出的 token 总数，或按该提供商响应格式中可用的 token 字段推算出总数。它不会根据你的提示词或生成文本的长度去估算缺失的 token。

图表把所选时段和筛选条件下的已记录 token 总数相加。每个请求归属于它开始时所在的 UTC 日历日。默认视图覆盖最近 31 个 UTC 日历日，包含今天。

- **Model** 按实际上游提供商和模型归集用量，跨多个已配置的提供商实例。
- **Person** 按发起请求的组织成员归集用量。
- **Team** 把每个人的用量归到他们当前所属的团队。属于多个团队的人对每个团队都有贡献，因此团队合计可能超过模型或个人的合计。没有团队的成员不会出现在团队视图中。

token 值为 0 不会在图上多出一根柱子。没有任何正向 token 用量的模型或个人会从图例中省略。上报的 0 仍然是一个已知数值，它和没有提供 token 总数的响应是两回事。

一个请求可能在失败或被取消之前就已上报了 token。这些已上报的 token 仍然计入。重试会生成另一个请求，该重试上报的 token 同样计入。

## 无法计量的项目

**无法计量的请求（uncountable query）**指 Gateway 没有拿到 token 总数的请求。这类请求不会为图表贡献任何 token。图表下方的说明会链接到本页；展开 **Uncountable query details** 可以查看所选时段和筛选条件下每个类别的请求数。

这些类别描述的是 Gateway 记录到的结果。它们不代表额外的 token，而且一个请求只属于一个类别。

### 提供商错误

提供商返回了错误，或者它的响应流在 Gateway 收到 token 用量之前就报了错。这可能包括提供商侧的限制、服务错误，或生成到一半时出现的错误。

如果提供商在出错前已上报了 token，Gateway 会把这些 token 计入，该请求就不算无法计量。

### 连接失败

Gateway 无法建立或完成到上游的连接，没有收到 token 总数。例如网络、TLS 或连接错误，可能让可用的提供商响应到不了 Gateway。

### 取消与中断

客户端在 token 用量到达之前取消了查询或断开了连接。你停止某个任务或连接掉线时都可能发生。如果历史汇总是在中断之后生成的，那些因 Gateway 中断而未完成的请求也会归到这一类。

提供商可能只在流式响应临近结束时才发送用量。收到了一部分生成文本，并不能保证 Gateway 拿到了最终的用量信息。

### 被拒绝的请求

Gateway 在把请求发给提供商之前就拒绝了这个请求。例子包括请求体无法完整读取、不受支持的操作或载荷、不可用的凭据，或请求者无权访问的模型。

这类请求没有可计量的上游 token 用量。即使校验拒绝了请求，或它的请求体上传被中断，只要所请求的模型仍可获得，Gateway 就会保留它。

### 已完成但没有上报用量

Gateway 记录到了成功的响应，却拿不到 token 总数。响应可能省略了用量、使用了无法识别的用量格式，或结束时没有最终的用量事件。仅凭成功的响应状态，不能说明全部用量信息都已收到。

### 较早的记录

一些较早的汇总含有缺失用量的总数，但没有保留按结果分类的完整明细。展开明细时，无法判定的类别会显示 **Unavailable**。Gateway 不会猜测缺失的类别，也不会用这些计数去重建 token 总数。

## 费用如何统计

费用视图会把每个请求记录的已知费用相加。有提供商上报的费用时，Gateway 就用它；否则根据已上报的 token 用量和可获得的模型定价来估算。

计算方式、缺失费用的处理，以及这些估算的局限性，见 [Token 费用](/zh/ai-gateway/token-costs)。
